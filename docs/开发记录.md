# 小聆掌机游戏厅 · 开发记录

> 记录时间：2026-10 ~ 2026-11
> 平台：聆思 Arcs Mini3（LS2663 + CH32V003 扩展板）
> 基础固件：arc SDK `mini-v3.1.0`
> 代码量：Lua 2178 行（`apps/`）+ 固件补丁 1209 行（`patches/`）

---

## 1. 一句话总结

在原厂"能跑 Lua"的基础上，把一个 240×240 的圆屏小设备做成了**有手感、有声音、可调试**的游戏厅：13 个画面、26 组程序化音效、进游戏自动念一段玩法讲解、一套在 PC 上就能复现真机崩溃的无头仿真器，以及 6 个让设备"能自证"的调试命令。

---

## 2. 平台约束：设计的第一因

所有看起来"奇怪"的写法，都是被下面这张表逼出来的。

| 约束 | 具体表现 | 后果 |
|---|---|---|
| 屏幕 240×240 | `screen.rect(x, y, w, h, color)` | 所有布局都是硬编码像素，没有布局引擎 |
| **参数只收整数** | C 侧一律 `luaL_checkinteger` | 传 `180.0` 直接抛 `number has no integer representation`，**整个小应用安装失败** |
| 矩形必须合法 | `1 ≤ w,h`，且 `x+w ≤ 240`、`y+h ≤ 240` | 算出 h=0 的柱子 = 崩溃 |
| 文字坐标受限 | `text(s, x, y)` 的 `x ≤ 239`、`y ≤ 224` | 底部提示语只能放在 222 |
| 一帧图形/文字有上限 | 原 16 条文字，补丁后 32 条 | 2048 的 16 格数字 + 分数就快满了 |
| 源码上限 64KB | `MINIAPP_SOURCE_MAX_BYTES` | `arcade.lua` 已 72KB，补丁把默认值调到 96KB（上限 128KB） |
| **精简 Lua 无 `pcall`** | 设备端没有保护调用 | 任何可能越界的参数都要在调用前夹取 |
| 单音蜂鸣器 | `buzzer.play(hz, ms)` 每次重开音频流 | 高频连发会互相打断，全部听不见 |
| 旋钮是绝对值 | `adc.read(7)` → 0..1023 | 没有"转了几格"的概念，必须自己做基线 |
| 帧节拍 20ms | 50fps | 物理量必须按 `dt` 积分，不能按帧累加 |

## 3. 整体架构

```
┌─────────────────────────────────────────────┐
│  apps/*.lua            游戏逻辑（纯 Lua）      │
│  ├─ 音效引擎 S / play_sfx / join_score        │
│  ├─ 绘图封装 rect/circle/line/text（取整）    │
│  ├─ 输入层 pressed() / knob_raw()             │
│  └─ 12 个 scene（init / update / draw）        │
├─────────────────────────────────────────────┤
│  miniapp 运行时（补丁）                        │
│  ├─ screen.* / gpio / adc / clock            │
│  ├─ buzzer.play（单音）                       │
│  └─ synth.play（4 声部乐谱）← 本次新增         │
├─────────────────────────────────────────────┤
│  固件：LS2663 + FreeRTOS + 音频 Player         │
│  CH32V003：exadc（旋钮）/ exgpiod（扩展 IO）   │
└─────────────────────────────────────────────┘
```

场景统一用三件套：

```lua
local SCENES = {}
SCENES.snake = { init = init_snake, update = update_snake, draw = draw_snake }
```

`update(dt)` 里画完就 `screen.present()`；切场景走 `set_scene(name)`，返回走 `PARENT` 表：

```lua
local PARENT = {
    prob_menu = "menu",
    dice = "prob_menu", coin = "prob_menu", galton = "prob_menu",
    converge = "prob_menu", monty = "prob_menu", binom = "prob_menu",
    snake = "menu", balance = "menu", target = "menu", g2048 = "menu",
}
```

这样每个页面只需要知道"我的上级是谁"，返回逻辑集中在一处，新增页面不会漏。

## 4. 功能清单

### 4.1 游戏大厅

主菜单 5 项：贪吃蛇 / 概率实验室 / 平衡挑战 / 打靶 / 2048。

操作约定（全部页面一致）：

- ↑↓ 选择，→ 进入
- 板载侧键**单击** = 返回上一级；在主菜单上 = `app.exit()` 退出小应用
- 每页底部印提示 `↑↓←→ 选择  侧键返回`，主菜单印 `侧键退出`

### 4.2 四个主场景

#### 贪吃蛇

| 项 | 值 |
|---|---|
| 网格 | 10px 格 × 22×22，游玩区 220×220，起点 (10, 18) |
| 速度 | 基础 24px/s，每吃一颗 +2.2px/s，上限 42px/s |
| 体节 | 记录头部轨迹点，按 8px 等距取点铺开，转弯自然成弧 |
| 转向 | 方向键**当帧生效**（不等下一格），头部眼睛立即翻转 |

关键改动是"像素级连续移动"：原版是整格跳（等效 53px/s），手感生硬且转弯是直角折线。改成头按像素连续前进后，转弯变成平滑弧线，同时速度反而更好控制。

#### 平衡挑战

一根会倾斜的杆，小球会往低处滑。旋钮做反向补偿，撑得越久分越高。

```lua
local acc  = off * 300 + (rnd() - 0.5) * 1100   -- 手动加速度 + 手抖噪声
bal.v = (bal.v + acc * s) * (1 - 2.2 * s)        -- 阻尼 2.2/s
bal.v = clamp(bal.v, -170, 170)                  -- 终端速度约 136px/s
bal.x = bal.x + bal.v * s
```

- 积分按**秒**（`s = dt/1000`），不按帧。之前按帧累加导致 20ms 一帧时物理快 50 倍，0.7 秒就落杆。
- 噪声项幅度 ±550px/s²，不操作大约 20 秒落杆；半秒内能救回来。
- 分数 = `floor(t / 100)`，即每存活 0.1 秒 1 分。

#### 打靶

| 项 | 值 |
|---|---|
| 发数 | 5 发 |
| 准星 | 每发在 44..196 随机重置（靶面 50..190，留余量） |
| 微调 | 旋钮**相对**转动，每发重建基线 |
| 抖动 | 落点 ±11px |
| 环数 | 距心 <10 → 10 环；<25 → 8；<42 → 6；<60 → 4；其余 2 |
| 反馈 | 枪口白圈闪 60ms + 弹孔留痕 + 环数文字 |

旧版准星由旋钮**绝对值**直接决定，每次开局都停在正中，等于不用瞄。改成随机落点 + 相对微调之后，每发都要重新找靶，旋钮才有了"瞄准"的意思。

#### 2048

4×4，格 44px、间距 4px，起始 (26, 32)。四方向合并，同一次移动里合并过的块不再参与二次合并（`i = i + 2`）。达成 2048 弹"→继续"，无路可走弹"→ 重开"。

合并音按块值升调：`merge2` 到 `merge6` 五个音，越大越亮；滑动是 25ms 的低音量噪声，连滑不吵。

### 4.3 概率实验室（7 个实验）

| 实验 | 玩法 | 教学点 |
|---|---|---|
| 掷骰子 | → 掷一次，830ms 抖动滚动，落点计入分布 | 均匀分布、频率稳定性 |
| 掷硬币 | → 掷一次，正反累计与占比 | 大数定律 |
| 高尔顿板 | 放球，小球逐层撞钉左右随机，入槽堆高 | 二项分布的形成 |
| 频率收敛 | 连续试验，实测频率曲线逼近理论线 | 频率 vs 概率 |
| 蒲丰投针 | ↑投 1 根 / ↓投 10 根，红=扎到线、蓝=没扎到；→ 切到 π 收敛曲线 | 几何概率、用频率反推常数 |
| 蒙提霍尔 | 三扇门选一，主持人开一扇空门，可换门 | 条件概率、直觉陷阱 |
| 二项分布 | n、p 可调（旋钮），柱状图与理论值对照 | 参数对分布形状的影响 |

高尔顿板每次放球触发 `drop`（放球）、`pin_tick`（撞钉，极短 20ms 三角波）、`bin_land`（入槽）；球在 8 个槽里逐层下落，堆叠高度超过 6 格自动压缩显示。

**蒲丰投针**（`play_buffon`）是唯一带"双视图"的页面：

- 视图 1 是针板：`cross = (hi >= lo)` 直接判断落点覆盖的 y 区间里有没有 `k` 让 `y = Y0 + k*D` 成立，红蓝两色就是结论本身，不靠图例。
- 视图 2 是 π 的收敛折线：横轴 `sqrt(投针数)` 做压缩（前段铺得开、后段收紧），纵轴固定 2.2~4.2，黄线 `3.1416`，末点红点标出当前估计——这是"越投越准"唯一看得见的证据。
- 旋钮两个目标（针长 L / 线距 D，`←` 切换），换任一参数都清空统计，因为那是换了实验。
- 一帧 256 个图元的硬限制下，屏上只画最近 160 根针，`共 N` 单独显示总数——第一版是 90 根，玩家会以为"针丢了"。

### 4.4 独立小应用

| 应用 | 说明 |
|---|---|
| `dice.lua` | 独立掷骰子，抖动动画 + 830ms 滚动乐谱；用作音效引擎的最小示例 |
| `coin.lua` | 掷硬币 |
| `galton.lua` | 高尔顿板 |
| `hwtest.lua` | 硬件自检：按键电平、旋钮 ADC 值、屏幕纯色块 |

`hwtest` 已从**游戏大厅**移除（大厅里放硬件自检很奇怪），但语音唤醒入口仍然保留 —— 它是排线/旋钮坏没坏的现场检查工具，不该跟着游戏一起消失。

## 5. 音效系统

### 5.1 为什么放弃 `buzzer.play`

`buzzer.play(hz, ms)` 每次调用都会**重新开一条音频流**。开流有几十毫秒的启动延迟，而骰子每 60ms 发一次 25ms 的"嗒"——**每一条都在启动阶段被下一条打断**，结果全部哑掉。打靶间隔长，所以那边还能听见"嘟"。

结论：高频音效不能靠"多调几次单音"，必须**一次提交一整段**。

### 5.2 乐谱格式

固件暴露的 `synth.play(notes)`：

| 字段 | 含义 |
|---|---|
| `delay_ms` | 相对乐谱起始的偏移 |
| `hz` | 频率 |
| `dur_ms` | 时长 |
| `voice` | 声部 1..4，同声部后音截前音 |
| `wave` | `square` / `triangle` / `noise` |
| `volume` | 0..100 |

Lua 侧包一层：

```lua
local function N(delay, hz, dur, voice, wave, vol)
    return { delay = delay, hz = hz, dur = dur, voice = voice, wave = wave, volume = vol }
end

local S = {
    gun = {
        N(0,   4300,  30, 1, "noise",   70),   -- 爆音
        N(0,    270,  60, 2, "square",  60),   -- 低频冲击
        N(30,  1500,  50, 1, "noise",   45),   -- 尾音
        N(70,   105, 110, 3, "square",  50),   -- 余震
    },
}
```

`play_sfx(name, delay)` 负责提交，`delay` 用来错开同一帧里的多个音效（比如"落杆"和"结算"）。

### 5.3 音效表（26 组）

| 分组 | 名字 | 用法 |
|---|---|---|
| 界面 | `move` `select` `back` `deny` | 菜单移动/确认/返回/拒绝 |
| 打靶 | `gun` `hit10` `hit8` `hit4` `miss` | 枪声与四档命中 |
| 骰子 | `dice_roll` `dice_land` | 滚动 13 下（间隔渐长）+ 落定"当" |
| 硬币 | `coin` | 叮当 |
| 高尔顿 | `drop` `pin_tick` `bin_land` | 放球/撞钉/入槽 |
| 贪吃蛇 | `eat` `die` | 吃与撞墙 |
| 平衡 | `fail` `warn` | 落杆、临界预警 |
| 2048 | `slide` `merge2..merge6` `win` | 滑动、按值升调的合并、达成 |
| 其他 | `deny` | 非法操作 |

### 5.4 组合：枪声 + 命中提示

枪声和"几环"提示如果分两次 `play_sfx`，第二条会掐掉第一条（又回到开流问题）。所以用 `join_score` 把两段拼成一条，后段整体延后 170ms：

```lua
local gun_hit10 = join_score(S.gun, S.hit10, 170)
```

4 种命中组合（10/8/4/脱靶）都是这样拼出来的，因此实际可播效果是 26 组乐谱 + 4 个拼接变体。

### 5.5 参数夹取

设备端没有 `pcall`，而 `hz` 必须在 100..5000、`ms` 在 20..3000，越界直接抛错。所以 `play_sfx` 里所有数字先夹取再提交 —— 这一条曾直接导致"游戏大厅打不开"（见踩坑记录 #6）。

## 6. 绘图封装层

所有绘制都走统一封装，不再直接调 `screen.*`：

```lua
local function iv(v) return math.floor(v + 0.5) end          -- 四舍五入成整数
local function _rect(x, y, w, h, color)
    if w < 1 or h < 1 then return end                         -- 非法矩形直接丢弃
    if x < 0 then w = w + x; x = 0 end
    if y < 0 then h = h + y; y = 0 end
    if x + w > 240 then w = 240 - x end
    if y + h > 240 then h = 240 - y end
    if w < 1 or h < 1 then return end
    screen.rect(iv(x), iv(y), iv(w), iv(h), color)
end
```

这一层挡住过两次真机崩溃：

1. **平衡挑战闪退** —— `off*46` 算出浮点 tilt，`screen.line` 拒收 → 取整解决。
2. **打靶弹孔崩溃** —— `h.x - 2` 带小数 → 同一个封装兜住（仿真器先报的）。

代价是"画错不报错"。所以仿真器把丢弃也计入统计，避免静默丢图。

## 7. 输入层

```lua
local function pressed(dir)   -- 只在"刚按下"这一帧为真
    local now = read_input()[dir]
    local was = last_input[dir]
    return now and not was
end
```

两个细节：

- **第一帧只做基线**。小应用刚启动时 gpio 首次采样会有瞬时高电平，若不丢弃会被误判成"按下了"——这条曾让游戏大厅直接启动失败。
- **旋钮做相对量**。`knob_raw()` 读 0..1023 绝对值；需要"转了多少"时，用 `kprev` 记录上一帧值，每发/每页重建基线。

## 8. 固件侧改造

补丁 `patches/0001-miniapp-arcade-runtime.patch`，10 个文件约 1200 行。

### 8.1 `synth.play` 绑定

`miniapp_runtime.c` 新增 Lua 函数：把 Lua table 解析成 `miniapp_score_t`（音符数组），投递给音频任务，由 `miniapp_synth` 按毫秒时间轴渲染 4 声部 PCM。

- 音符上限与总时长在解析时校验，非法直接 `luaL_error`，不会崩到音频线程。
- 每段 64ms 分块生成 PCM（`int16_t pcm[1024]`），不做整曲预分配。

### 8.2 `app.exit()`

```c
/* 不在 Lua 回调里拆 VM，只投递事件 */
miniapp_post_event(MINIAPP_EVENT_EXIT);
```

### 8.3 `tts.speak()`

进游戏念一段玩法说明，靠的是把运行时里已有的 TTS 队列开一个 Lua 口子：

```lua
tts.speak("蒲丰投针。针随机落在平行线上……")   -- 异步，返回 speech_id
function on_tts_result(id, res) end            -- 全局回调，status = completed | failed
```

三个必须知道的约束：

- **异步且不阻塞**：请求发出去就返回，手照样能按。所以"边讲边玩"不需要额外做线程。
- **同时只允许 1 条**（`MINIAPP_TTS_MAX_PENDING = 1`）：连翻几页时不能一股脑丢出去，代码里用一个"只念最后一段"的待发槽排队。
- **文本 1..512 字节**：中文 3 字节/字，`INTRO` 每段控制在 150 字节内。

真机上踩过一个坑：语音服务卡住不回包时，音频通道会被它一直占着，`synth.play` 全部失败 → 整个游戏静音。所以 20 秒没回包就主动 `tts.cancel()` 释放通道，连续两次不回包则本次运行不再尝试。

### 8.4 调试命令（`miniapp ...`）

| 命令 | 作用 |
|---|---|
| `list` | 列出已注册小应用 |
| `run <id>` | 启动 |
| `status` | 帧数、掉帧、最大帧耗时、`last_error` |
| `key <dir> <0\|1>` | 注入方向键电平 |
| `btn` | 模拟侧键单击 |
| `screen` | 打印最近一帧全部图形与文字（图元 >64 时只打末尾 32 条） |
| `glyph <hex...>` | 打印字形位图与步进 |
| `audio` | 合成器遥测 + TTS 请求数/成功数/最近状态 |

`screen` 的实现是在 `miniapp_ui.c` 加一个快照：present 时在锁内拷贝一帧，命令再读出来。这样 headless 会话里也能确认"用户看到的是什么"。

### 8.5 资源上限

| 配置 | 原值 | 新值 | 原因 |
|---|---|---|---|
| `MINIAPP_MAX_TEXTS` | 16 | 32 | 2048 的 16 格数字 + 分数 + 提示超限 |
| `MINIAPP_HEAP_MAX_BYTES` | 393216 | 524288 | 72KB 源码 + 双 VM 回滚时紧张 |
| `MINIAPP_SOURCE_MAX_BYTES` | 65536 | 98304 | `arcade.lua` 涨到 72KB，超过默认上限装不进去 |

| 骰子音效 | 滚动整段 + 落定 `3 notes / 226ms` |

## 11. 设计取舍

| 选择 | 理由 | 代价 |
|---|---|---|
| 一个 `arcade.lua` 装 13 个场景 | 共享音效/输入/绘图封装，省重复代码与堆 | 单文件 72KB，离 96KB 上限还有余量 |
| 全量取整而非按需取整 | 一处兜住所有浮点，杜绝整类崩溃 | 画错时静默丢弃，要靠仿真统计发现 |
| 音效一次提交整段 | 绕开"每次开流、互相打断" | 乐谱要手写时间轴，调参靠听 |
| 旋钮做相对微调 | 绝对值直连会让打靶永远停在正中 | 每页要维护 `kprev` 基线 |
| 固件调试命令常驻 | 开发期能自证画面与音频 | 占 flash；发布版应 Kconfig 裁掉 |
| 分离 `dice` 与大厅内 `dice` | 一个是独立应用，一个嵌在概率实验室 | 两份滚动逻辑，需同步维护 |

## 12. 后续可做

- **分辨率无关布局**：现在全是硬编码像素，换屏就全废；可抽一层 240 基准的换算。
- **音效参数外部化**：乐谱写死在 Lua 里，调音要改代码；可做成表驱动 + 一组预设。
- **发布版裁剪**：`miniapp` 调试命令与 `hwtest` 用 Kconfig 开关隔离，省 flash 与内存。
- **源码分片**：`arcade.lua` 已 72KB，可拆成 `core` + `games` 两个小应用，或做运行时 require。
- **录制回放**：仿真器已能注入按键序列，可把一局操作录成脚本做回归。
