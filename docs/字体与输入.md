# 字体 · 输入 · 布局速查

做像素级界面时需要背下来的几组数字。都是**真机实测**，不是文档抄的。

---

## 1. 字体

| 项 | 值 |
|---|---|
| 文件 | `lv_font_chinese_16.bin` |
| 格式 | 1bpp，行优先，位为 1 表示点亮 |
| 字高 | 16px（含行距，实际字面 15px） |
| cmap | 覆盖 ASCII、常用汉字、U+2190..U+2199 箭头、部分符号 |

### 验证字形：`miniapp glyph`

不要去离线解析 cmap —— 索引基数差 1 就会整体错位，得出"没有这个字形"的错误结论（见[踩坑记录 #8](踩坑记录.md)）。设备端直接打：

```sh
adb shell miniapp glyph 2190 2191 2192 2193
```

输出形如：

```
U+2190 adv=16 w=14 h=7
.##.......####.
..#.......#....
...#.....#.....
....#...#......
```

### 实测步进（advance）

| 字符类 | 宽 | 说明 |
|---|---|---|
| 汉字 | 16px | 与箭头同宽 |
| U+2190 ← / U+2192 → | 14px（位图），adv 16px | 左右箭头横向长、纵向窄（14×7） |
| U+2191 ↑ / U+2193 ↓ | 7px（位图），adv 16px | 上下箭头纵向长（7×15） |
| 数字 `0-9` | 9px | 等宽 |
| 空格 | 4px | 窄空格，**不是** 8px |
| ASCII 字母 | 约 8-9px | 不等宽 |

> 注意：**位图宽度 ≠ 步进宽度**。箭头位图只有 7-14px，但步进是 16px，所以按位图宽度居中会偏。

### 文案居中

因为步进不统一，居中要按字符累加宽度：

```lua
local function text_width(s)
    local w = 0
    for _, cp in utf8.codes(s) do
        if cp == 32 then w = w + 4                 -- 空格
        elseif cp >= 0x30 and cp <= 0x39 then w = w + 9   -- 数字
        elseif cp >= 0x2190 and cp <= 0x2199 then w = w + 16
        elseif cp >= 0x4E00 then w = w + 16        -- 汉字
        else w = w + 9 end                          -- 其他 ASCII 近似
    end
    return w
end

local function center_text(s, y, color)
    screen.text(s, math.floor((240 - text_width(s)) / 2), y, color)
end
```

精简 Lua 没有 `utf8` 库时，退化成按字节判断：3 字节序列 = 汉字（16px），1 字节 = ASCII。

## 2. 布局

屏幕 240×240 圆形，**四角会被切掉**，有效区域近似内切圆（半径 120）。

| 区域 | y 范围 | 用途 |
|---|---|---|
| 标题行 | 2..22 | 页面名 + 分数；标题通常居中，分数靠右 |
| 内容区 | 26..200 | 主画面 |
| 底部提示 | 218..238 | 操作提示（`text` 的 y 上限是 224） |

硬性约束：

- `text` 的 `x ∈ [0, 239]`，`y ∈ [0, 224]`
- 矩形必须完全在屏内：`x + w ≤ 240`、`y + h ≤ 240`
- 圆形贴近四角的部分不可用，重要信息放在 `x ∈ [20, 220]`、`y ∈ [24, 216]`

常用常量：

```lua
local W, H = 240, 240
local BACK_LABEL = "侧键 返回"        -- 宽 68px（16*4 + 4），x=164 时右边界 232
```

## 3. 按键

模块：**Risym 大按键模块** —— 12×12mm 轻触开关 + 大圆帽（黑/红/绿/蓝/黄），20×12mm PCB，3Pin `VCC/GND/OUT`，板载上拉与防抖。输出高电平有效（部分版本可用跳线选低有效，接线前先量一下）。

| 方向 | 引脚 | 电平 |
|---|---|---|
| ↑ | PA0 | 高电平有效 |
| ← | PA1 | 高电平有效 |
| ↓ | PB7 | 高电平有效 |
| → | PB6 | 高电平有效 |
| 侧键（功能键） | — | 由 `on_button_click("function")` 回调 |

因为模块自带防抖，软件层只做边沿检测，不再加延时消抖——加反而会让快速连按丢键。

### 边沿检测

只关心"刚按下"，不关心长按：

```lua
local function pressed(dir)
    local now = read_input()[dir]
    return now and not last_input[dir]
end
```

### 第一帧必须只做基线

上电首次采样会瞬时读到高电平。若不丢弃，启动那一帧就会被当成"用户按着方向键"，轻则菜单跳一格，重则触发越界参数导致安装失败（见[踩坑记录 #4](踩坑记录.md)）。

固件侧也做了防护：`s_gpio_ready[3]` 按端口记录已配置引脚，首次配置后延时 2ms 再采样。

## 4. 旋钮

| 项 | 值 |
|---|---|
| 模块型号 | **Risym 电子积木 旋转电位器模块**（10kΩ 线性，机械行程 270°，20×20mm PCB，带 Φ3mm 安装孔） |
| 引脚 | PD4（扩展排针） |
| 通道 | `exadc` ch7 |
| 读数 | `adc.read(7)` → 0..1023（10 位 ADC = 1024 级） |
| 输出特性 | 顺时针电压升高，线性，**无档位、无段落感** |

### 是电位器，不是编码器

模块是"线性电位器 + 3Pin 排针"（`GND/VCC/OUT`），不是旋转编码器：**读不到"转了几格"，只知道"现在在哪"**。270° 行程对应 0..1023，所以每度约 3.8 个 ADC 计数。

这决定了两种用法：

- **绝对用法**（平衡挑战、二项分布调参）：`off = (k - 512) / 512`，映射到 -1..1。
- **相对用法**（打靶微调）：记 `kprev`，`delta = k - kprev`，每次进入新目标时重建基线。

```lua
local function knob_delta()
    local k = adc.read(7)
    local d = k - (kprev or k)
    kprev = k
    return d
end
```

### 死区与钳制

电位器在两端有机械回差，`0..8` 和 `1015..1023` 读数不稳：

```lua
local function knob_raw()
    local k = adc.read(7)
    if k < 8 then k = 8 elseif k > 1015 then k = 1015 end
    return k
end
```

### 每帧只读一次

`adc.read` 走 I2C 到协处理器，频繁读会拖慢帧。所有逻辑共用同一帧的读数，不要在每个 `draw` 分支里各读一次。

## 6. 一帧的预算

| 项 | 上限 |
|---|---|
| 文字条数 | 32（补丁后；原 16） |
| 图形条数 | 由 `MINIAPP_MAX_SHAPES` 决定，足够画 2048 的 16 格 + 网格 |
| 建议帧耗时 | < 20ms（50fps 节拍） |

2048 是最吃预算的页面：16 格底色 + 16 格数字 + 标题 + 分数 + 提示 = 16 条文字、20+ 个矩形，正好卡在旧上限附近 —— 这就是把上限从 16 提到 32 的直接原因。
