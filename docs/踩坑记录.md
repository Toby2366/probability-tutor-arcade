# 踩坑记录

按"症状 → 根因 → 怎么定位 → 教训"记录。这些坑的共同点是：**报错信息指向的地方，几乎从来不是真正的原因**。

---

## 1. 平衡挑战一打开就闪退

**症状**

进"平衡挑战"页面立刻退回大厅，`miniapp status` 里 `last_error`：

```
bad argument #2 to 'line' (number has no integer representation)
```

**根因**

```lua
local tilt = off * 46            -- off 是浮点，tilt 也是浮点
screen.line(16, 120 - tilt, 224, 120 + tilt, YELLOW)
```

C 侧 `screen.line` 用 `luaL_checkinteger` 取参，Lua 5.3 的整型/浮点子类型在这里是硬区分的 —— 传 `180.0` 不等于传 `180`，直接抛错。

**定位**

先怀疑物理参数（`off` 越界？除零？），但报错明确说"没有整数表示"。真正的问题是：**整个 `screen.*` 家族都只收整数**，而 Lua 里除法、乘法天然产浮点。

**修复**

在 `arcade.lua` 顶部统一封装 `rect/circle/line/text`，全部 `math.floor(v + 0.5)` 后再下发，同时过滤非法矩形。

**教训**

> 在只收整数的绘图 API 上，"算出来是数字"不等于"能画"。所有绘制入口必须只有一个，否则漏一处就崩一页。

## 2. 打靶打完一发就崩

**症状**

发射后弹孔画不出来，页面卡死/退出。

**根因**

```lua
screen.circle(h.x - 2, h.y - 2, 2, hole_color)   -- h.x 带小数
```

准星位置由旋钮插值算出，是浮点；减 2 之后还是浮点。

**定位**

这次是**仿真器先报的**：`_sim.cjs` 的假 `circle` 照抄了整数校验，跑随机按键 80 帧时立刻在 `circle#1` 抛错。

**修复**

同一层封装兜住（见上一条）。弹孔坐标先取整再入表。

**教训**

> 第 1 条修完不等于修完同类问题。**用同一个入口收口，才能一次修一类**；否则就是打地鼠。

## 3. 平衡挑战 0.7 秒就落杆

**症状**

刚进页面，杆瞬间倒下，根本来不及操作。

**根因**

```lua
-- 错误写法：按帧累加
bal.v = bal.v + (off * 300) * 0.02
```

物理量按"每帧"累加，但帧率是 50fps —— 相当于把 1 秒的力在 0.02 秒里用完，实际加速度放大了 50 倍。

**定位**

把 `dt` 打出来才发现每帧 20ms，而代码里写的是常数 `0.02`（本意是"一帧 20ms"）。逻辑上没错，但一旦帧率变化/掉帧就会漂；真正的问题是**没有用真实 dt**。

**修复**

```lua
local s = dt / 1000                 -- 秒
bal.v = (bal.v + acc * s) * (1 - 2.2 * s)
```

**教训**

> 任何随时间演化的量都必须乘真实 `dt`。写死"每帧多少"在 50fps 稳定的设备上看着正常，掉一帧就全乱。

## 4. 游戏大厅根本打不开

**症状**

`miniapp run arcade` 返回失败，设备停在语音界面；`status` 显示安装错误。

**根因**（两个叠在一起）

1. `gpio.read` **首次采样会瞬时读到高电平**，被误判成"用户按着方向键"。
2. 于是启动那一帧就触发了菜单移动音效 `beep(700, 12)` —— 但 `buzzer.play` 要求 `ms >= 20`，12ms 越界，抛错 → 整个小应用安装失败。

**定位**

这是最难查的一类：**页面代码看起来完全正常，错在"启动瞬间的输入误判"**。最后是靠 `miniapp key` 逐键注入 + 在 `on_start` 里打日志，才看出第一帧就有按键。

**修复**

- `read_input()` 第一帧只做基线，不产生任何"按下"事件。
- 固件侧 `s_gpio_ready[3]` 按端口记录已配置引脚，首次配置后延时 2ms 再采样。
- 音效参数统一夹取（`ms` 夹到 20..3000）。

**教训**

> 上电首采不可信。而且**一个越界的小参数足以让整个应用装不上**，音效这类"非核心"代码也必须做参数校验。

## 5. 骰子既没动画也没声音

**症状**

点掷骰子，画面直接跳结果，一声不响。

**根因**（两个独立问题）

1. **动画**：大厅里的骰子本来就是"按一下直接出结果"，从没实现过抖动滚动（独立 `dice.lua` 才有）。
2. **声音**：`buzzer.play(hz, ms)` 每次调用都重开一条音频流；骰子每 60ms 发一次 25ms 的"嗒"，**每一条都在启动阶段被下一条打断**，全部哑掉。

**定位**

Lua 侧完全不报错。加了 `miniapp audio` 遥测后才看清：`synth` 播完段数是 0 —— 不是"播了没声"，而是**根本没播完过**。

**修复**

改用 `synth.play(notes)`，把 13 下撞击写成**一整段 830ms 乐谱**一次提交（间隔逐渐拉长 = 越滚越慢），落定再单独一声。同时补回抖动动画。

**教训**

> "没有报错"和"功能正常"是两件事。**必须有能观测到结果的埋点**（这里是一条 `miniapp audio`），否则只能在"看得见/听得见"的层面猜。

## 6. 二项分布把 p 调到极端就崩

**症状**

旋钮转到最边上，页面崩。

**根因**

```lua
local h = math.floor(p * 160)     -- p 极小时 h = 0
screen.rect(x, y, 12, h, color)   -- h=0 非法
```

**修复**

`h = math.max(h, 1)`，同时顶部 `rect` 封装也过滤 `w/h < 1`。

**教训**

> 概率/比例算出来的高度天然会取到 0。**"尺寸可能为 0"要在算完立刻兜住**，别等它走到 API 边界。

## 7. 贪吃蛇开局自己撞死

**症状**

一进贪吃蛇，蛇头直接朝自己身体里钻，立刻 game over。

**根因**

`recompute_pts()` 里构造方向向量时符号写反，初始体节排在头的**前方**而不是后方，第一次移动就自我碰撞。

**修复**

方向向量取反，并让初始体节沿"反方向"铺开。

**教训**

> 初始化状态要和移动规则用**同一个方向约定**。这类错误不会报错，只会"看起来莫名其妙地死掉"。

## 8. 离线解字体，得出"箭头渲染不出来"的错误结论

**症状**

想用 ↑↓←→ 代替 W/A/S/D 做按键提示，离线解析 `lv_font_chinese_16.bin` 的 cmap 后判断"这些码位没有字形"，于是准备改用文字。

**根因**

cmap 子表的 `glyph_id_start` 是**索引基数**，实际字形号 = `glyph_id_start + offset`，差 1 就会把所有字形整体错位。当时按 `+offset` 直接取，得到的全是相邻字符。

**定位**

不猜了，直接在固件里加设备端命令 `miniapp glyph <hex>`：把字形位图按行打成 `#`/`.` 打出来。

```
miniapp glyph 2190 2191 2192 2193
```

真机输出证明 U+2190..2193 **字形完全正确**：

| 码位 | 字形 | 位图尺寸 | 步进 |
|---|---|---|---|
| U+2190 ← | 正确 | 14×7 | 16px |
| U+2191 ↑ | 正确 | 7×15 | 16px |
| U+2192 → | 正确 | 14×7 | 16px |
| U+2193 ↓ | 正确 | 7×15 | 16px |

**修复**

13 处文案改为箭头，并按实测步进（16px，与汉字同宽）重算居中 x。

**教训**

> 离线解析二进制格式时，"结构读对了"和"语义读对了"是两回事。**能用设备自证的事，不要用推理定论**。这也是后来加 `glyph`/`screen`/`audio` 三个命令的直接原因。

## 9. 仿真器里中文比较永远失败

**症状**

`_sim.cjs` 想用 `text.s:find("共掷", 1, true)` 判断是否落定，永远返回 nil。

**根因**

读源码用了 `latin1` 编码，中文被按单字节解码，再传给 fengari 时又做了一次 UTF-8 编码 —— 二次编码，和目标字符串自然对不上。

**修复**

`fs.readFileSync(path, 'utf8')`。

**教训**

> 跨语言跑中文源码，**输入解码必须一次到位**。否则你调的不是业务逻辑，是编码学。

## 10. 侧键返回"有时不灵"

**症状**

有的页面按侧键能返回，有的没反应；主菜单按侧键也不退出。

**根因**

最初只有部分场景自己处理了侧键，且没有统一的"上级"概念；主菜单也没有 `app.exit()` 可调（固件当时没这个绑定）。

**修复**

- 固件加 `app.exit()` 绑定。
- Lua 侧用 `PARENT` 表统一返回，`on_button_click("function")` 一处收口。
- 每页底部印操作提示，主菜单印"侧键退出"。

**教训**

> 交互约定必须**集中实现 + 页面显式声明**。分散在各页面里的返回逻辑，一定会漏。

## 速查：崩溃信息 → 最可能的原因

| 报错 | 先查什么 |
|---|---|
| `number has no integer representation` | 绘制参数是不是浮点（除法/插值结果） |
| `invalid rectangle` | `w/h` 是否为 0 或超出屏幕 |
| `out of range` | 坐标越界，或音效 `hz/ms` 越界 |
| `screen.text limit is 32` | 一帧文字太多（2048 数字格 + 分数 + 提示） |
| 安装失败但无 Lua 报错 | 启动第一帧的输入误判、或某个音效参数越界 |
| 有声音调用但没有声 | 用 `miniapp audio` 看是否"播完过"；多半是开流被打断 |
| 页面正常但行为怪 | 初始化状态与运行规则的方向/单位不一致 |
